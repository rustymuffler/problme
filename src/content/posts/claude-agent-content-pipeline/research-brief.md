# Research Brief: How I Built a Fully Automated Content Pipeline with Claude Agents (and What Broke First)
Date: 2026-07-21

## Key Statistics and Data

- **CompanyOS runs an entire company on ~2,000 lines of markdown across 12 skill files, 5 commands, 2 agents, and 8 MCP server connections** (Linear, Gmail, Google Calendar, Help Scout, Notion, Sentry, Stripe, Granola). — Source: [Running a Company on Markdown Files](https://adventuresinclaude.ai/posts/2026-02-21-running-a-company-on-markdown-files/) (Published: 2026-02-21). Directly comparable scale reference for probl.me's own AGENTS.md-based pipeline (roughly a dozen agent roles defined in markdown, no orchestration framework).
- **More than 140 npm packages were compromised as of 2026-06-20** in a campaign Microsoft attributed to Sapphire Sleet (BlueNoroff), a North Korean state actor, the first confirmed nation-state attribution to a targeted AI-framework supply chain campaign. — Source: [ALT CISO Daily Briefing, 2026-06-22](https://labs.cloudsecurityalliance.org/research/alt-ciso-briefing-2026-06-22/) (Published: 2026-06-22). Relevant context for the article's supply-chain-override story: the governance gate exists precisely because this class of attack is escalating, not theoretical.
- **A separate npm compromise (AsyncAPI) republished five malicious package versions across four package names within roughly 90 minutes** on 2026-07-14, discovered the same day. — Source: [Microsoft Security Blog, 2026-07-15](https://www.microsoft.com/en-us/security/blog/2026/07/15/unpacking-asyncapi-npm-supply-chain-compromise-import-time-payload-delivery/) (Published: 2026-07-15). `[UNVERIFIED — optional]`: not required for the article, but available if a second concrete recent-compromise example is wanted to show this is a live, ongoing pattern, not a one-off.

## Counterarguments to Address

- **"You should just use a real framework (LangGraph, CrewAI, etc.) instead of a markdown file."** Industry commentary (LinkedIn engineering: "always try to buy, don't try to build") argues frameworks are usually the better call for production multi-agent systems. Acknowledge this directly: the markdown/AGENTS.md approach is a reasonable starting point for a one-person, low-volume pipeline like probl.me's, not a claim that it scales indefinitely or is right for every team. CompanyOS's own philosophy, "it doesn't need another orchestration layer, it needs domain knowledge", is a good frame for this: the argument isn't "frameworks are wrong," it's "start with the simplest thing that encodes your actual process, add structure when you actually hit its limits."
- **"Overriding a security gate is exactly the kind of process failure this article is supposedly warning against."** Fair challenge. Address it honestly: the override wasn't a bypass of judgment, it was an application of it, the scan flagged recency, not malware, and the decision was made after checking the actual evidence (no malware indicators, track record of the source). The article should be explicit that "hardening the process" doesn't mean "never override anything", it means making overrides deliberate, evidenced, and logged rather than reflexive.
- **"AI agent supply-chain attacks are a bigger threat than one recency-gate false positive suggests, doesn't this normalize risky behavior?"** Use the 140-package Sapphire Sleet stat to show the override decision was made in a landscape where the risk is real and escalating, which raises the bar for what counts as "comfortable enough to override," not lowers it. This should read as taking the threat seriously, not dismissing it.

## Addendum: Workflow-Tool Alternatives (added 2026-07-21, second research pass)

Richard asked whether a dedicated workflow/orchestration tool would serve probl.me better than the AGENTS.md markdown approach. A follow-up research pass evaluated the specific alternatives below. All URLs verified live via direct fetch before inclusion.

- **Claude Code Dynamic Workflows** — generates orchestration scripts on the fly, fans work across parallel subagents. Anthropic positions it for hours-or-days-long engineering work (bug investigation, large migrations, security audits, architecture analysis) and explicitly warns it "can consume substantially more tokens than a typical Claude Code session." Wrong shape (parallel fan-out vs. sequential handoff) and wrong cost profile for a twice-weekly, six-step content pipeline. — [InfoQ, 2026-06](https://www.infoq.com/news/2026/06/dynamic-workflows-claude-code/), verified directly.
- **n8n** — already in probl.me's stack for the Umami analytics flow, and it now has a mature AI Agent node (multi-agent orchestration, MCP, RAG). The real cost isn't setup, it's ongoing maintenance (Docker updates, SSL renewal, backup testing), roughly 2-5 hours/month even for a small instance. Real overhead for a linear six-step flow with no branching. — [Multi-Agent Orchestration with n8n in 2026](https://medium.com/@angelosorte1/multi-agent-orchestration-with-n8n-in-2026-from-concept-to-real-world-ai-systems-bae68fa7ba03), [The Real Cost of Self-Hosting n8n in 2026](https://expresstech.io/the-real-cost-of-self-hosting-n8n-in-2026/).
- **Temporal (durable execution)** — the one genuine counterargument found. A markdown-file, single-session pipeline has no crash recovery: if Claude Code is interrupted mid-pipeline, there's no automatic resume from that exact point, and a rerun could make different decisions than the interrupted run did. Temporal's own example: a travel-booking agent that restarts and books a different destination than the first attempt. This is a real, unaddressed gap in probl.me's current setup. Temporal's own case studies (OpenAI Codex, NVIDIA GPU orchestration) target production/enterprise scale, not solo low-volume use. — [Of Course You Can Build Dynamic AI Agents With Temporal](https://temporal.io/blog/of-course-you-can-build-dynamic-ai-agents-with-temporal), verified directly, quote confirmed.
- **GitHub Actions as agent-orchestration substrate** — emerging pattern for teams running agent-augmented CI/CD at scale; not a fit for a pipeline that already runs synchronously inside one Claude Code session. — [GitHub Resources: What is AI Agent Orchestration?](https://github.com/resources/articles/what-is-ai-agent-orchestration)

**Bottom line used in the article:** switching away from AGENTS.md is premature for probl.me's current volume and shape (sequential, six steps, twice a week, human-in-the-loop). The Temporal durability gap is real and named honestly rather than dismissed, with the practical mitigation (manual rerun / lightweight checkpoint file) framed as sufficient until volume or complexity actually grows.
